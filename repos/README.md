## History kaise preserved hai

Har import ek **merge commit** hai jiske 2 parents hain:

1. Pehla parent = OmniRoute ka us waqt ka HEAD
2. Dusra parent = source repo ka original commit

Isliye source repo ki poori history (saare commits, authors, dates) object store mein
maujood hai. Kisi bhi sub-repo ki original history dekhne ke liye:

```bash
# merge commit ke dusre parent ko follow karo
git log --follow repos/n8n/

# ya seedha source commit se
git log 5f9602b19e4b513c939af44cea5ea7ede58b0555
```

## Kisi sub-repo ko update karna

```bash
git subtree pull --prefix=repos/n8n \
  https://github.com/duniyakarahasyamedia-hash/n8n.git master
```

## Kisi sub-repo ko wapas alag nikalna

```bash
git subtree split --prefix=repos/n8n -b n8n-extract
```

## Large files & Git LFS (note)

GitHub ne push ke waqt kuch badi files (>50MB) flag ki thin — ye **blocking nahi**
hain (sab 100MB hard limit se neeche hain), bas recommendations hain:

| File | Size | Status |
| --- | --- | --- |
| `repos/MoneyPrinterTurbo/resource/fonts/STHeitiLight.ttc` | ~53 MB | HEAD par maujood |
| `repos/MoneyPrinterTurbo/resource/fonts/STHeitiMedium.ttc` | ~53 MB | HEAD par maujood |
| `crawl4ai/models/onnx/model.onnx` | ~86 MB | sirf purani history mein (ab delete) |
| ek 92 MB model file | ~92 MB | sirf purani history mein (ab delete) |

Kyunki in repos ki **poori history preserve** karni thi, history rewrite karke ye files
nahi hatayi gayi hain. Agar aage jaake repo size kam karna ho to in files ko **Git LFS**
mein migrate kiya ja sakta hai:

```bash
# 1. Git LFS install karo (https://git-lfs.com), phir:
git lfs install

# 2. Large binary types track karo
git lfs track "*.ttc" "*.onnx" "*.bin" "*.pth" "*.safetensors"

# 3. History migrate karo (sirf bade files, --everything poori history rewrite karega)
git lfs migrate import --include="*.ttc,*.onnx" --everything

# 4. Force-push karo (history rewrite ke baad zaroori)
git push --force origin arena/019ffbc1-omniroute
```

> ⚠️ `--everything` poori history rewrite karta hai (saare commits ke naye SHA banenge),
> isliye team ke saath coordinate karke hi karna. Warning non-blocking hai, so ye
> optional hai.
